# ADR 7: IDE workspace (Monaco + xterm.js + node-pty) with separate edit clones and edit leases
Status: proposed (defaults in docs/PHASE2.md section 4)
Context: Guy wants the app to double as an IDE: edit files, see git diffs, commit, use terminals, and see each agent's workspace and shell. The reference project JSM HQ (jsmastery-pro/jsm-hq) has terminals (xterm.js + node-pty) but no editor or diff UI.
Decision: Monaco editor and diff editor (bundled locally, lazy-loaded); xterm.js in the UI; `@lydell/node-pty` (prebuilt N-API binaries) in the orchestrator, shipped per-platform in the installers; git via `execFile` argv with an allowlist. Guy edits in a dedicated per-project clone ("My workspace") that no agent uses; the orchestrator's base clone stays a read-only mirror because it is reset on sync. Agent workspaces are read-only in the IDE while a run is active; Guy may take over (soft-stop + checkpoint) and hand back. Saves use sha256 preconditions (409 on conflict). Guy's pushes never target main/master. Everything is loopback + token + Origin/Host checked.
Alternatives: CodeMirror 6 (lighter, weaker diff/IDE feel); WebContainers (cloud-ish, browser-only, not local files); embedding VS Code/code-server (heavy, separate server and auth); editing the mirror or live agent worktrees (data loss, conflicts).
Consequences: Larger UI bundle (mitigated by lazy loading); a native module to package for 4 targets (CI pty smoke test required); a full-shell terminal widens the attack surface, so it relies on the loopback/token model and is documented as such.
